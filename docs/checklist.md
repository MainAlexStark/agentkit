# Чеклист «агента на пять звёзд» — что есть в agentkit

## 1. Агентный цикл — `agent.py`

| | Что | Где / как |
|---|---|---|
| ✅ | Цикл модель → инструменты → результат → модель | `Agent._loop` |
| ✅ | Условия остановки: ответ без инструментов, лимит шагов, отмена, ожидание человека | `RunStatus` |
| ✅ | Последний шаг без инструментов — модель обязана подвести итог | `max_steps` |
| ✅ | Параллельные вызовы: подряд идущие read-only — одновременно, остальные по порядку | `_execute` |
| ✅ | Стриминг текста и рассуждений | `TEXT_DELTA`, `THINKING_DELTA` |
| ✅ | Повторы с backoff (429/5xx/обрыв), переход на запасную модель | `ModelRouter` |
| ✅ | Отмена в любой момент | `Agent.cancel`, кнопка «стоп» |
| ✅ | Ошибка инструмента → текст модели, а не падение | `_invoke` |
| ✅ | Защита от зацикливания (N одинаковых вызовов) | `loop_guard` |
| ✅ | Заплатка истории, если процесс упал между вызовом и результатом | `_for_model` |
| ✅ | Прогоны-сироты после перезапуска помечаются ошибкой (только без живой блокировки — соседние процессы не задеваются) | `AgentService._fail_orphans` |
| ✅ | Уровень рассуждений (effort) | `AgentSpec.reasoning_effort` |
| ✅ | Дописать сообщение, пока агент работает: очередь в базе, агент читает её между шагами (не разрывая пары вызов-результат) и перед «готово»; иначе — сразу после прогона | `ak_inbox`, `Agent._take_inbox`, `AgentService.send` |

## 2. Контекст — `context.py`

| | Что | Где / как |
|---|---|---|
| ✅ | Системный промпт из слоёв: правила ядра → промпт агента → правила хоста → skills → MCP → отложенные инструменты → окружение → память | `build_system_prompt` |
| ✅ | Порядок под кэш: стабильное первым, дата (без времени) и память — в конце | там же |
| ✅ | Prompt caching для Claude через OpenRouter (cache_control на системном и последнем сообщении) | `openai_compat._with_cache_control` |
| ✅ | Автосжатие истории моделью small; история в базе не теряется | `compact`, `effective_history` |
| ✅ | Обрезка длинного вывода + полный текст в blob, чтение по частям | `truncate_text`, `read_output` |
| ✅ | Отложенные инструменты: в промпте имя, схема — через `tool_search` | `registry.py` |
| ✅ | Учёт токенов и стоимости по шагу, прогону, пользователю, модели | `Usage`, `/api/usage` |
| 🟡 | Оценка токенов без токенизатора (±25%) | достаточно для порога сжатия |

## 3. Инструменты — `tools/`

| | Что | Где / как |
|---|---|---|
| ✅ | `@tool` из сигнатуры функции: схема, описание аргументов, валидация до вызова | `tools/base.py` |
| ✅ | Файлы: read (с номерами строк), write, edit точной заменой, glob, grep — только внутри рабочей папки | `tools/files.py` |
| ✅ | Shell с таймаутом (выключен по умолчанию) | `tools/shell.py` |
| ✅ | web_fetch с защитой от SSRF (и после редиректа) | `tools/web.py` |
| 🟡 | web_search: Tavily; Yandex Search API — перенести из EI_doc | `SearchProvider` |
| ✅ | MCP: Streamable HTTP (JSON и SSE, сессия), stdio, Bearer, переподключение, include/exclude, read-only по аннотациям | `mcp.py` |
| ✅ | Упавший MCP-сервер не роняет агента, статус виден в UI | `MCPManager.status` |
| ✅ | Свои MCP-серверы из интерфейса: адрес, вход (нет / токен / OAuth), заголовки, отложенная загрузка; проверка до сохранения; правка, выключение, удаление; токены наружу не отдаются; применяется во всех процессах | `/api/mcp/servers`, `/api/mcp/test`, kv `config/mcp_servers` |
| 🟡 | Свои серверы — общие на всех (добавляет admin) | личные серверы пользователя — когда понадобятся |
| ✅ | MCP OAuth 2.1: поиск метаданных (RFC 9728/8414/OIDC), DCR, PKCE S256, resource, обновление с ротацией refresh, повтор после 401, отзыв; кнопка «Подключить» в UI | `oauth.py`, `/api/mcp/{имя}/connect`, `/oauth/callback` |
| 🟡 | OAuth-токен общий на сервер (подключает admin) | личные токены каждого пользователя — когда понадобятся (как в OpenSeller) |
| ✅ | Виджеты в ответе инструмента: таблица, kv, картинки, выбор | `ToolResult.ui` |

## 8. Безопасность и права — `permissions.py`

| | Что | Где / как |
|---|---|---|
| ✅ | Режимы: default, accept_edits, plan, readonly, auto, bypass (только admin) | `Mode` |
| ✅ | Правила allow / ask / deny по имени и шаблону аргумента: `shell(git status*)` | `Rule` |
| ✅ | Подтверждение — карточка с понятным видом действия; переживает перезапуск | `ApprovalRec`, `describe=` |
| ✅ | needs_approval по аргументам — доменная страховка даже в auto | `Tool.needs_approval` |
| ✅ | Результат инструмента — данные, не инструкции (правило в промпте) + права в коде | `CORE_RULES` |
| ✅ | Рабочая папка — граница для файлов; контейнер не от root | `files.resolve`, Dockerfile |
| ✅ | Токены только в заголовке, сравнение за постоянное время | `server/auth.py` |
| ❌ | Маскирование секретов в выводе и журналах | — |
| ❌ | Лимиты расходов на пользователя/день | есть учёт, нет отсечки |

## 9. Асинхронность и автономность

| | Что | Где / как |
|---|---|---|
| ✅ | Прогон в фоне, закрытая вкладка его не обрывает | `RunManager` |
| ✅ | Задачи по cron, хранятся в базе, пропуски не догоняются пачкой | `scheduler.py`, `/api/schedules` |

| ✅ | Расписание и подтверждения не срабатывают дважды при нескольких процессах | `claim_schedule`, `claim_approval` |

## 12. Модели — `llm/`

| | Что | Где / как |
|---|---|---|
| ✅ | OpenRouter, Yandex AI Studio, OpenAI, Ollama — один OpenAI-совместимый клиент | `openai_compat.py` |
| ✅ | «провайдер:модель», роли main/small, запасные модели | `ModelRouter` |
